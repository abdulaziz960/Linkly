# مركز الشروحات

المسار `/dashboard/tutorials` يتطلب تسجيل الدخول. زر «الشروحات» موجود بجانب الأيقونات العلوية وفي شريط الجوال. قراءة الشروحات لا تمنح صلاحيات؛ صفحات الإعداد تطبق صلاحيات الحساب وباقته عند فتحها.

## المحتوى والمقاطع

`app/dashboard/tutorials/guides.json` هو مصدر العناوين والنبذات والتصنيفات والخطوات وأمثلة API. لكل فصل وقت بداية `start`، وتُحسب مدته حسب التطبيق الفعلي مع وقفة للقراءة. لا تعتمد الصفحة على مدة ثابتة للفصول. الصفحة تدعم البحث العربي والتصنيفات والتنقل إلى الفصل وصورًا من التطبيق في بطاقات المكتبة.

المقاطع تسجيلات شاشة متواصلة من واجهة المشروع الحقيقية في حساب `browser-workspace` المعزول. تُسجل حركة التركيز والنقر والكتابة، وتملأ واجهة التطبيق الفيديو بالكامل بنسبة 16:9 وبدقة Full HD (1920×1080)، مع عنوان صغير عائم للخطوة. يبدأ كل شرح باختيار الصفحة من القائمة الجانبية ثم التبويب المناسب عبر النقر الفعلي. يحفظ هذا الفصل الأول مع `kind: navigation` ويعلّم الملف بـ `frameLayout: full-screen`. لا يوجد عمود شرح جانبي داخل المقطع. تظهر أسهم حمراء وإطار حول الزر أو الحقل المستهدف، مع عبارات عربية قصيرة ووقفة بعد التطبيق. جميع المقاطع بلا مسار صوتي، والمشغل مكتوم افتراضيًا. تبقى ملفات VTT والخطوات المكتوبة بديلًا قابلًا للقراءة.

ربط سلة وزد مستقل عن ربط قناة واتساب. إذا كان الحساب التدريبي غير متصل بالمتجر أو كانت بيانات تطبيق المزود غير مضبوطة، يشرح التسجيل ذلك صراحة ويقدم تجهيز الإعدادات قبل الاتصال. اكتمال ربط المتجر وإرسال إشعار فعلي يحتاجان حساب متجر حقيقيًا أو تجريبيًا مفوضًا وقوالب واتساب معتمدة. تفويض مزود خارجي مثل Meta أو سلة لا يُحاكى كنجاح؛ يظهر مكان الربط والإعدادات المحلية، وتذكر الخطوات أن التفويض يتم لدى المزود. القنوات التي تعرض «قريبًا» موصوفة بهذه الحالة. تجربة Webhooks تستخدم استجابات تدريبية في المتصفح لعرض أدوات الإدارة دون الاتصال بمستقبل خارجي أو اختلاق سجل تسليم ناجح. طلبات API الخاصة بقراءة العملاء وإضافتهم وأخطاء 400 و401 تنفذ فعلًا ضد الخادم المحلي، وتُعرض الاستجابات الفعلية.

شرح الرد الآلي يشمل الأدوات، بناء مسار كامل، وأنواع الخطوات الثلاثة عشر ورفع صورة وفيديو وملف نصي. لا توجد خطوة «طلب API» داخل محرر الرد الآلي الحالي؛ الربط البرمجي مشروح عبر أدوات المطورين وواجهات API الموجودة.

## إعادة تسجيل المقاطع

1. شغّل نسخة محلية معزولة بالبيانات التجريبية الخاصة باختبارات المتصفح (`e2e/server.mjs`). لا تستخدم حساب مستخدم حقيقيًا.
2. جهّز فريقًا باسم «خدمة العملاء» وموظفًا تدريبيًا في هذه القاعدة فقط لشرح خطوات التحويل.
3. شغّل المسجل من جذر المشروع:

```sh
node scripts/generate-tutorial-videos.mjs
# أو إعادة تسجيل شروح محددة:
node scripts/generate-tutorial-videos.mjs --only bot,bot-build,bot-types
```

المسجل يرفض المضيفات غير المحلية ويتحقق من هوية `browser-owner` ومستأجر `browser-workspace` قبل أي تعديل. يوقف طلبات المتصفح الخارجية ولا يكمل نوافذ التفويض. بيانات الدخول الثابتة تخص اختبار المتصفح فقط. ينشئ مفاتيح API تدريبية ويلغيها بعد التسجيل؛ يخفيها بصريًا في المقاطع. آثار التشخيص تبقى في مجلد مؤقت خارج ملفات الموقع.

المخرجات في `public/tutorials/`: فيديو MP4 (H.264 بلا صوت) وصورة JPG وتسميات عربية VTT لكل شرح. تُحدّث بداية كل فصل والمدة و`visualArrows` (مع `narrated: false`) في مصدر المحتوى بعد اكتمال ترميز الفيديو. تحديث المصدر محمي بقفل محلي وكتابة ذرية لدعم دفعات تسجيل مستقلة. لا توجد تبعيات على خدمة فيديو خارجية أو تشغيل تلقائي. لا يستخدم المسجل أي توليد صوتي. تستخدم الصفحة مشغلًا بعرض المحتوى مع تكبير الشاشة والتحكم بسرعة الشرح، وإصدارًا جديدًا لروابط الوسائط عند تحديث المقاطع.

## التحقق

```sh
node scripts/verify-tutorial-recordings.mjs
npx playwright test e2e/tutorials.spec.ts
```

يغطي تسجيل الدخول، ظهور مدخل الشروحات، البحث والتصفية، تشغيل الفيديو والتقديم بين الفصول، صفحات الرد الآلي وأمثلة API، توفر جميع المقاطع، وعرض الجوال دون تجاوز أفقي.
